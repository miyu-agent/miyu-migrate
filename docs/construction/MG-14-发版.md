# MG-14 发版设施

照 core1 11-05 的单子：迁移各类都做完了，补上发版要的东西，好让主人在真数据根上跑。这一步不打标签、不推官方源（两样都要主人当面点头，
core1 去问），真跑什么时候做也是 core1 去问主人。

## 做什么

1. **打包模板**（`.github/workflows/release.yml`）：照 miyu-render、miyu-memes、miyu-im 的写法，推 `v*` 标签时三种系统（linux-x86_64、
   macos-aarch64、windows-x86_64）各用共用的 `miyu-agent/packages/.github/workflows/pack.yml@main` 打一个 `.miyu`、传进这个标签的
   Release。构建一段：`cargo build --release --locked -p miyu-migrate`，程序拷进 `miyu-migrate/bin/`（Windows 带 `.exe`），许可证拷进包
   文件夹（AGPL 随包发）。`miyu-migrate/bin/` 在 `.gitignore` 里。
2. **清单**（`miyu-migrate/package.toml`）：版本 0.1.0，三种 targets 照旧；去掉 `protocol = [1, 1]`，只留 `[package]` + `[command]`。
   原来的写法打不了包：核心认 `[command]` 或协议版本就要一张程序表（`[ui]`、`[process]`、`[builtin]`、`[worker]`），`miyu pkg pack` 报
   `missing_key`。迁移是人在终端里跑的一条子命令，哪张程序表都不对：`[ui]` 会出现在 `ui.head` 的选项里，`[process]` 会在包列表里多一个
   开关、打开了核心会拉起一个不讲协议的程序。core1 11-05 定：核心加一种「只带子命令的包」（没有程序表、只写 `[command]` 的算 bundle，
   bundle 能写 `[command]`；`protocol` 照旧只给带程序的包写），核心的改动 core1 做。迁移程序连核心走 miyu-client 的握手，协议版本
   hello 里自己带，用不着清单那一格。
3. **README「主人在真数据根上跑」**：fish，一行一个代码块。装包（本地 `.miyu` 或官方源）、`miyu migrate --help` 核对转交；停旧核心（8300
   那个，给出命令、写明什么时候停主人定；没停的迁移程序自己拦）；`miyu core stop` + `cp -a --reflink=auto` 给新数据根拍底；
   `miyu migrate ~/.miyu`；报告在 `<新数据根>/root/documents/旧版 Miyu 迁移/<时刻>/`；回退：整个撤是换回拍的底，只撤一部分的照报告删直接放进
   数据根的那几样，经核心、im 写进库里的几样只能整个撤；旧根本来不动。

4. **留给人的挪进数据根**（core1 11-05 定，`run.rs`）：压缩包、清单、两份报告，以及 im、表情包没装时留着待导的 `qq-records.jsonl`、
   表情包的包，写进新数据根的 `root/documents/旧版 Miyu 迁移/<时刻>/`（`run::keep_dir`，同 MG-10 放文档的那一层）：人看得见、卸包
   不删、跟着数据根一起备份。包的状态目录只放中间产物（`<时刻>/work` 解开核对的那一份、`<时刻>/stage` 暂存），用完整个删。同一秒
   重跑照旧拒（看的是数据根里那一层）。空间检查改成照目录算那块盘：放压缩包的那块要旧根两倍（同一块盘时连解出来的那一份），状态
   目录那块要一倍；目录还没建的问它最近的已有上一层，查完之前什么都不建。

5. **报告里照抄的命令加引号**（彩排查出来的，`report::shell_path`）：留给人的目录名「旧版 Miyu 迁移」带空格，报告里「装上以后跑」的
   `miyu im records import <文件>`、`miyu pkg install <表情包>` 原来不加引号，照抄进终端会拆成几个参数。只有字母、数字和
   `/._-+:,@%~` 的照原样；别的用单引号（fish、bash、zsh、PowerShell 都照字面）；带单引号的用双引号、`"` `$` `\` `` ` `` 前面加反斜杠。

## 坑

- **演练副本先查一遍配置文件**：以后每次演练拷了旧根的副本，先跑 `find <副本> -name 'config.jsonc*'`，确认只剩没有 key 的再演。
  MG-13 那次只删了 `config.jsonc` 本身，`config.jsonc.bak*` 九份留在副本里（报告只写了份数和大小，副本演完删了），靠记性不靠谱。
- **`miyu pkg remove miyu-migrate` 连状态目录一起删**：原来压缩包、清单、两份报告都在状态目录 `var/lib/miyu-migrate/<时刻>/` 里，
  压缩包是旧版数据唯一的整份备份，迁完人很自然会卸这个包。见下面第 4 条，挪进数据根了。
- **新版默认数据根也是 `~/.miyu`**（`DataRoot::locate`，没设 `MIYU_HOME` 的）：所以一般用户要先把旧目录挪开（README 开头那三行）；
  主人这台的新数据根由 `MIYU_HOME` 指到 `~/.cache/miyu-tui-home`，旧目录原地迁。
- **主人这台的 `miyu` 是临时部署的包装脚本**：它照子命令名转交，列表里没有 `migrate` 的会打开终端界面。要在包装脚本里加上；部署归
  主会话，这一步不动它，交接时告诉 core1。
- **主人这台部署的核心（11-03 `43ff9ee97`）比这个仓库钉的（`65b0c2188`）早 59 个提交**，也还不认只带子命令的包：真跑之前要先换核心。
- **旧版程序改了名**：本机 `~/.local/bin/miyu` 已经是新版包装，旧版是 `miyu.0.7.0-local.bak`（还有 10-22、10-23 两份开发版的备份）；
  停旧核心照旧版自己的 `daemon stop`。写这一步时旧核心没在跑（`daemon.lock` 里的进程号已经不在，8300 没人听）。

- **重跑一次多一整份压缩包**：每跑一次都在「旧版 Miyu 迁移」下新建一个时刻目录，压缩包（主人的旧根约 1G）、`qq-records.jsonl`
  （约 48M）、表情包的包都再写一份。彩排两遍是 2.4G。确认最后一次没问题以后，旧的时刻目录自己删。
- **`miyu pkg pack` 要写 `--target`**：清单写了三种 targets 的，不写会报「需要指定目标系统」。CI 的模板由共用的 pack.yml 带上。

## 怎么验

- 照 core1 合进去的核心试打一次包：`miyu pkg pack miyu-migrate`（隔离的 `MIYU_HOME`），再 `miyu pkg info <打出来的 .miyu>`，看种类、
  子命令、三种 targets。
- 照那个核心在隔离的数据根上装一次、跑 `miyu migrate --help`（只印用法）。
- 发版模板只在推标签时跑，这一步不打标签，所以 CI 跑不到它；写法照 miyu-render 的逐格对过。
- 单元（`run/tests.rs`）：留给人的落在数据根那一层、状态目录的中间产物删了；同一秒重跑拒；放压缩包的盘不够（报那一层）、状态
  目录那块盘不够（数据根在另一块盘上，状态目录还没建）都拒、什么都不建；正好够的能跑；假的空间函数同真的一样，问的目录要已经有。
- 手写变异 6 个都抓住（状态目录那块不查、两倍改一倍、`<` 改 `<=`、不找已有的上一层、中间产物不删、同一秒不拒）；`<=` 和不找上一层
  两个第一轮没抓住，补了「正好够」和「问的目录要已经有」。
- 照旧：fmt、clippy（Linux 和 `x86_64-pc-windows-gnu`）、测试，三平台 CI。

## 彩排（11-05，真跑之前照 README 从头走一遍）

照 core1 11-05 的单子：核心用 PK-1 合进 main 的 `95afeae90`（debug，`-p miyu -p miyu-sandbox`），迁移程序是这个分支的 release 版，
照发版模板的样子拷进包文件夹再打包，不用 `cargo run`。全在 `~/.cache/miyu-remake/rehearse/MG-14/` 下，临时数据根 `home/`
（`MIYU_HOME`、`MIYU_RESOURCES` 指核心工作树的 `resources/`、`MIYU_PROGRAM` 指这个核心），不碰主人的数据根；演完整个删了。

1. **副本**：拷之前看 `~/.miyu/daemon.lock`：进程 1691 已经不在，8300 没人听。`cp -a --reflink=auto ~/.miyu old`，删锁，
   `find old -name 'config.jsonc*' -print -delete` 删了 10 份（`config.jsonc` 和 9 份 `.bak*`），再 `find` 一遍是 0。副本 1.6G。
   配置一类因此没有可迁的（报告写「旧根里没有读得懂的配置」）；配置走真核心的那一段 MG-6 演过。
2. **打包**：`miyu pkg pack miyu-migrate` → 「需要指定目标系统」（见坑）；`miyu pkg pack miyu-migrate --target linux-x86_64` →
   `miyu-migrate-0.1.0-linux-x86_64.miyu`，2697529 字节。
3. **看包**：`miyu pkg info ./miyu-migrate-0.1.0-linux-x86_64.miyu` → 编号 miyu-migrate、版本 0.1.0、「提供：命令 miyu migrate」、
   装后 7.0 MiB。
4. **装包**：`miyu pkg install ./miyu-migrate-0.1.0-linux-x86_64.miyu --yes`（彩排里不问；README 照问着写）→ 「已安装 miyu-migrate 0.1.0」。
5. **核对转交**：`miyu migrate --help` → 用法，退出码 0；`miyu migrate` 不带参数 → 用法，退出码 2，什么都不动。
6. **拍底**：`miyu core stop` → 退出码 0；`cp -a --reflink=auto home home.before-migrate`。
7. **第一遍**：`miyu migrate old` → 48 秒，退出码 0，印两行：报告、给 agent 的，都在
   `home/root/documents/旧版 Miyu 迁移/20261104T215500Z/`。目录里 7 样：`报告.md`、`给agent.json`、`miyu-0.7.tar.zst`（1.0G，9314 个文件，
   原始 1.6G）、`miyu-0.7.manifest.json`、`qq-records.jsonl`（48M）、两个表情包的包。包的状态目录 `var/lib/miyu-migrate/` 里什么都没留。
   各类：人格 3、会话 118、记忆 121（40 条没导：她自己的、太长的）、技能 2、知识库 6626 篇、文件 251（3 样没拷，报告逐条写了）、登录态 5 处只报；
   QQ 记录、赞助、表情包：im、赞助插件、miyu-memes 没装，报告写装上以后跑哪一行（临时根里不装 im：装上会启用、抢主人在用的
