# MG-17 赞助记录照总线上的名字导

核心设计 `67-总线.md` 的 BUS-4 里和迁移程序有关的那一份（2026-11-11）。

## 为什么

- 核心加了用户态总线：包在清单 `[export]` 里声明提供的名字，方法写成 `<名字>.<短名>`，调的一方照名字调（`bus.call`），不写包编号。
- 赞助插件（im 施工 I-211）已经在总线上提供 `sponsor`，清单导出的是 `sponsor.import`、`sponsor.export`；不带前缀的 `import`、`export`
  只是还登记着的别名，插件说了等迁移程序改完名字再去掉。
- 迁移程序是人在终端里跑的，走人的连接：照包编号的 `package.call` 以后照旧能用，这一步不是因为要断才改，是把方法名换成对方清单里
  导出的那一个，免得别名去掉时断掉。

## 搜了什么

全仓库搜 `package.call`、`bus.call`、`"import"`、`"export"`、`"add"`、`miyu-im-sponsor`、`miyu-memes`、`miyu-im`，经核心调别的包的只有一处：

- 赞助记录（`sponsors.rs`）：`package.call {"package": "miyu-im-sponsor", "method": "import"}`。这一步改。
- 表情包（`memes.rs`）不调表情包的 `add`：把旧库做成内容包，经核心自己的 `package.install {path}` 装。核心的方法不上总线，不改。
- QQ 消息记录（`records.rs`）是起 `miyu im records import` 这条命令，不经核心调包。不改。
- 赞助的 `export` 没人调。
- `package.list` 看装没装（赞助插件、表情包）是核心的方法，照旧照包编号看。

## 改了什么

1. `sponsors.rs`：导的那一次改成 `bus.call {"name": "sponsor", "method": "import", "params": {"entries": […]}}`（短名一段，核心拼成
   `sponsor.import`）。回应、出错的形状同 `package.call`，新加几笔、本来就有几笔照旧读。报告这一项的 `target` 写 `bus.call sponsor.import`。
2. 先照 `package.list` 看插件装没装照旧：没装的不调，报告写装上以后重跑。
3. 装着但是调不到的，报告写清楚升级哪一个，不落进「没导进去（代码：原话）」那一句含糊的：
   - `no_provider`（总线上没有 `sponsor`：插件是 I-211 以前的，或者停用了）、`unregistered`、`not_exported`（没有 `sponsor.import`）：
     「总线上调不到赞助插件的 `sponsor.import`，装着的插件太旧或者停用了……把赞助插件 `miyu-im-sponsor` 升级（停用了的先启用）以后重跑迁移」；
   - `unknown_method`（核心不认 `bus.call`：核心是总线以前的）：「这一版 Miyu 不认 `bus.call`，太旧……把 Miyu 升级以后重跑迁移」。
   两句都带原因码，都写「重跑不会多出来」。记录留在压缩包里（`archived`）。别的原因（插件拒了、程序没连着）照旧写「没导进去（代码：原话）」。
4. **不退回旧名字再试**：迁移程序和包一起发新版，对方是旧的就让人升级，不为旧版多留一条路。

没动的：钉的核心提交（65b0c2188，总线以前的）。连核心的门面只是把方法名、参数照写的发出去，`bus.call` 不用新门面；这一处的测试用假
核心，没有对真核心的集成测试，所以不用为它换钉。实际跑的时候要核心带 BUS-2（ee77f789d）以后的。

## 怎么验

- 单元（`sponsors/tests.rs`）：
  - 导的那一次发出去的是 `bus.call`，`name` 是 `sponsor`、`method` 是 `import`，不带 `package`；`target` 是 `bus.call sponsor.import`。
  - 新测试 `an_old_plugin_or_an_old_core_is_told_apart_from_a_refusal`：`no_provider`、`unregistered`、`not_exported` 写升级插件，
    `unknown_method` 写升级 Miyu；都只问一次（不退回旧名字）。
  - 没装的不调、插件拒了的照原话写、没有记录的不问核心：照旧。
  - 先红：实现没动时这两条红（假核心收到 `package.call`：「没想到会调 package.call」）。
- 本机照 `ci.yml`：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、
  `cargo test --workspace --locked` 全过（整机锁里编）。
- 没测到的：没有在真核心上装着新版赞助插件导一遍。要看的一步：核心带 BUS-2 以后的、赞助插件带 I-211 以后的，
  `miyu migrate <旧目录>`，报告的赞助一项写「新加 N 笔，M 笔账本里本来就有」。
