# MG-12 赞助记录：经赞助插件的导入口子导进账本

照细则第十一节已定第 4 条（im 施工 I-131，im 设计 03 第五节）。另带一个登录态的小修（core1 合 MG-11 时提的）。

## 做什么

1. 读旧会话库的 `sponsor_records`（没有这张表的当没有），照 `record_id` 一行一笔：
   - `platform`：`onebot`（和空的）写 `qq`；
   - `user`：`sponsor_id` 是数字的写 `qq:<号>`，不是数字的（只有名字）写 null；`name` 照 `sponsor_name`，空的写 null；
   - `amount` = `amount_minor`/100、`converted` = `cny_minor`/100（整的写整数，有零头的写小数）；`currency` 大写，`base` 写 `CNY`；
   - `rate`：`currency` 是 `CNY` 的写 1（旧库写 0）；不是的 `fx_rate` 大于 0 照搬、等于 0 写 null；
   - `at` 是 `sponsored_at` 换成毫秒；`by`：`recorded_by` 是数字的写 `qq:<号>`、别的照写、空的 null；`note` 空的 null；`venue` 写 null。
2. `package.list` 里有 `miyu-im-sponsor` 的，`package.call {"package": "miyu-im-sponsor", "method": "import", "params": {"entries": […]}}`，
   报告写新加几笔、本来就有几笔（插件照平台、人、时刻、金额、币种去重，重导是空操作）；没装的报告写装上以后重跑；插件拒的照它的原话写
   （原话只有第几笔哪一格不对，不带名字金额）。名字、号是别人的：报告只写条数。没有记录的不问核心。
3. 登录态：闲鱼的凭据拷过去以后 Unix 上设成文件 0600、目录 0700，不跟着源文件的 0644（`fs::copy` 照源文件的权限位拷）。

## 怎么验

- 单元：一行换成一笔的每一格（号、名字、分换元、同币种汇率 1、汇率 0 写 null、毫秒、记账的人、备注）；照会话库读、没有表的；插件装着的导、
  没装的不调、拒了的写原话；没有记录的不问核心。登录态的权限：源文件 0644 拷过去是 0600、目录 0700。
- 演练（主人旧根的副本）：58 笔，演练核心没装赞助插件，报告写装上以后重跑；58 笔都是金额为正、有号或名字、时刻读得懂的（插件的
  检查都过得去）。im 那边 I-131 拿同一份旧库对着主人现在的账本演练过：新加 0、本来就有 58。
