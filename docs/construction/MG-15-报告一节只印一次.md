# MG-15 报告里同一种只印一节

sub1 彩排 RL-6 时在主人旧根的副本上看到：给人的 `报告.md` 里「persona-settings」这一节印了两遍。这一步照代码和测试复现、修好，
发 0.1.1。没读主人的数据根。

## 现象

「每一类」下面 `### persona-settings` 出现两次，「没迁的」那张表里 `persona-settings` 也是两行，每行一个路径；`给agent.json` 的
`items` 里同样是两项同名的。

## 根因

- `personas::read`（`personas/read.rs`）每找到一份 `personas/<scope>/persona.toml` 推一条 `Extra { why: "persona-settings" }`；
- `run::persona_items` 原来一条 `Extra` 推一项 `Item`，`what` 照 `why` 定，`source` 是那一份；
- `Report::human` 照 `items` 逐项印 `### <what>`，「没迁的」那张表也逐项一行。

主人旧根里 `default`、`dev` 两个人格都有 `persona.toml`，于是同名的两项、两节。同一个毛病还在头像上：`data/prompts/<名字>.json` 的
`avatar_path` 指的头像不在了，一个人格一条 `avatar-missing`，两个以上就是两节 `persona-avatar`。`dev-prompt`、`system-prompt` 各只有
一个文件，碰不上。

查过别的路径：`personas::read` 在 `run::run` 里只调一次；别的类各自只推一项（`leftovers` 的 `outside/<路径>` 一个路径一个名字，
也不印节标题）。所以只有 `persona_items` 这一处。

## 改法

- `run::persona_items`：只报不迁的几样先照 `why` 分组（照读到的先后，第一次出现的位置定节的位置），一种一项，`source` 把几份路径用
  「、」并起来（同 `leftovers::item` 列几处的写法）。人读的那张表和给 agent 的 `source` 都是这一串，看得出是哪几份文件。四种
  （persona-settings、dev-prompt、system-prompt、persona-avatar）一样处理。
- `report.rs` 不兜底，只在 `Report::items`、`Item::source` 的文档注释写明「一类只一项、几份的 `source` 用「、」并起来」。理由：在印的
  时候合并只修得了给人的那份，`给agent.json` 还是两项；而且两项同名的 `status`、`format`、`migrated` 可能不一样，印的那一层不知道该
  怎么合，悄悄合掉反而把产出那一类的毛病藏起来。改在产出的地方，再用测试把「整份报告每一类只一项」钉住（下面）。

## 怎么验

- 单元 `run::tests::the_same_kind_of_extra_is_one_section_listing_every_file`：旧根照主人那样 `default`、`dev` 都有 `persona.toml`，
  再加两个头像不在了的人格，真走一遍 `run`（假核心）。断言：`给agent.json` 里每个 `what` 只一项；`persona-settings` 的 `source` 是
  `personas/default/persona.toml、personas/dev/persona.toml`，`persona-avatar` 的是 `data/prompts/乙.json、data/prompts/甲.json`；
  `报告.md` 里这两节各一个 `### ` 标题，「没迁的」表里各一行、带着那一串路径；整份 `报告.md` 的 `### ` 标题不重复。
- **不修时红**：先只加测试、不改 `run.rs`，编了跑这一条：挂在「给 agent 的那份每一类只一项」，18 项去重剩 16（persona-settings、
  persona-avatar 各两项）。再临时去掉给 agent 那几条断言重编再跑：挂在「给人的那份 persona-settings 只一节」，`left: 2`、`right: 1`。
  恢复测试、改 `run.rs` 以后这一条过。
- 改法本身就是那个变异（逐份推一项）；路径的分隔、先后测试按整串比，换分隔符、倒过来都抓得住。
- 照旧：fmt、clippy（Linux 和 `x86_64-pc-windows-gnu`）、全部测试，三平台 CI。
