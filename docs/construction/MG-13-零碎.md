照 DESIGN 第五节和 core1 11-05 定的清单。这一步什么都不写进新数据根、不连核心：前面各类没管到的，每一样在报告里一项，写明在压缩包的
哪个路径、旧格式一句话、多大或几条，给 agent 的那份照着就能接着迁（主人 11-04 定：用户要的话自己让 agent 迁，迁移程序给出路径就行）。

## 做什么（`leftovers.rs`）

1. 留在压缩包里的（`archived`）：用量（`usage_records` 条数）、上键历史（另数会话库的 `repl_history`）、QQ 的图片文件头像、配置的手动
   备份、网页（密码只写有没有）、语音、定时提醒、别的旧状态；成员的家目录只数个数；会话库里平台的表（插件键值照插件数，写「新 im 没有
   对应的，要重做」；表情引用、会话绑定数条数）；记忆的经历、日记、改动、旧向量照人格数。
2. 定时提醒（core1 定选 (a)，先存档）：给 agent 的那份写清路径、条数、还没到点几条，旧格式（JSON 数组，一条一个一次性提醒，`label`
   是内容，`due_at` 是 Unix 秒的绝对时刻，`time` 是人当时说的原话，`status`、`audio_file`），新版对应的方法 `schedule.add`，参数写「未核实」。
3. 派生的（`skipped`，`derived/…`）：日志、缓存、知识库的向量、旧版内置默认库、模型缓存这些，新版自己重建；给人看的报告合成一行
   「N 处」，给 agent 的逐条。
4. 数据根外面的（`skipped`，`outside/…`）：`~/.local/bin/miyu`、fish 钩子、`~/.gemini/config/agents/miyu`、`~/.gemini/antigravity-cli`、
   `~/.cache/miyu/voice-models`、`~/.local/state/miyu`，在的才报，「确认是旧版的、用不着了再删；删不删由你定」；`~/.local/bin/miyu` 里
   写着 miyu-remake 的照实写「这是新版的包装脚本，不是旧版的，别删」。家目录由 `Plan.home` 给，测试不给。
5. 报告：给人看的最后加一节「旧数据根」：旧目录一个字节没动，完整压缩包在哪、几个文件、原来多大、整个包的 SHA-256、逐文件清单在哪，
   确认迁完、用了一阵没问题以后再删旧目录，删由人自己来；开头那句「可以删」挪到这一节。数据根外面的单独一节。

  不在的不报、不给家目录不看）；报告里派生的合成一行、数据根外面一节、旧数据根是最后一节、给 agent 的照样逐条；字节数的写法。
