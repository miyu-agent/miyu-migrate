# MG-16 报告写的版本照包清单

MG-15 时记下的现成小毛病：报告的 `migrate` 字段、会话包里的 `miyu-migrate <版本>` 读的是 `CARGO_PKG_VERSION`，工作区版本一直是
0.0.0，所以主人实测的报告里会看到「miyu-migrate 0.0.0」，容易以为装错了。core1 11-07 定在主人打 v0.1.1 之前修，标签打在这一步上。

## 改法

挑小的那种：工作区版本 `[workspace.package] version` 改成和 `miyu-migrate/package.toml` 一样的 0.1.1（`Cargo.lock` 里本 crate
那一格跟着改），代码不动。两边要一起改，`Cargo.toml` 那一行上面写了注释。

另一种是代码里改成照包清单的版本（编进程序时读 `package.toml`）：要多一段读清单的代码，以后也不用记着改两处；但这个仓库同 im
一样照工作区版本走，改一处配一条测试守着就够，选了小的。

## 怎么验

- 新测试 `run::tests::version_matches_the_package_manifest`：`env!("CARGO_PKG_VERSION")` 和 `package.toml` 里写的版本一样。
  工作区版本留着 0.0.0 时这条红（`left: "0.0.0"`、`right: "0.1.1"`），改成 0.1.1 后绿。以后发版只改清单、忘了改
  `Cargo.toml` 时它红。
- 本机照 `ci.yml`：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、
  `cargo test --workspace --locked` 全过（整机锁里编）。

## 发版

标签 v0.1.1 打在这一步合进 main 以后的提交上（由项目主人打，写进 sub1 的主人脚本）。
