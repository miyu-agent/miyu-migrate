# 旧版 Miyu 数据迁移（miyu-migrate）

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

这个仓库是新版 Miyu 的一个软件包，用来把旧版 Miyu（0.7.x）的数据目录迁移到新版 Miyu。安装这个软件包以后，Miyu 会多出一条命令 `miyu migrate`。

迁移前先停止旧版，再把旧目录挪开，然后安装软件包并运行迁移：

```
mv ~/.miyu ~/.miyu-0.7        # 先停掉旧版，再把旧目录挪开：旧目录占着 ~/.miyu 时新版核心无法启动
miyu pkg install migrate
miyu migrate ~/.miyu-0.7
```

每一步的具体做法、迁移了哪些内容、哪些内容没有迁移、出了问题怎么处理，可以看 [从 0.7 旧版迁移](https://github.com/miyu-agent/miyu/blob/main/docs/zh/guide/migrate.md)。

迁移程序先把旧目录整个打成压缩包，逐个文件核对，然后只从解压出来的副本读取数据，通过新版核心的协议写入新版，最后生成两份报告：一份给人看；另一份给 AI 读，写明没有迁移的内容在压缩包里的哪个路径、旧格式是什么样，需要的时候你可以让 AI 接着迁移。迁移程序不会修改旧目录。压缩包和报告放在新数据根的 `root/documents/旧版 Miyu 迁移/<时刻>/` 里，因此你能直接看到它们，卸载这个软件包也不会删除它们，备份数据根时它们也会一起备份。

终端里输出的文字和给人看的报告会根据语言使用中文或英文。连上核心以后，迁移程序使用核心握手时返回的语言（界面语言、系统语言）；连上核心以前（例如显示帮助、报告无法连接核心的错误时），迁移程序使用系统语言（`LC_ALL`、`LC_MESSAGES`、`LANG`），以 `zh` 开头的是中文，其他的是英文。英文的目录叫 `Old Miyu migration/`，两份报告分别叫 `report.md`、`for-agent.json`。给 AI 读的那份报告在两种语言下结构相同；迁进新版的数据（会话、记忆、知识库的名字、文件所在的目录）不随语言变化。

迁移程序以在终端里运行它的用户的身份连接新版核心（读取数据根的 `run/token`）；如果核心没有运行，迁移程序会用 `miyu core` 启动核心。开始迁移之前，迁移程序会先检查两件事：一是旧版是否已经停止（`daemon.lock`）；二是硬盘空间是否足够，存放压缩包的那块硬盘需要有旧目录大小两倍的空闲空间，因为压缩包按不压缩计算，还要加上解压出来核对的那一份。解压出来的那一份放在迁移软件包的状态目录里，用完就会删除。

目前会迁移以下内容：

- **人格**：旧版的 Miyu 会新建成一个名字叫 Miyu 的人格，提示词取自旧版原文（`crates/miyu-migrate/legacy/`），你改过的角色扮演提示和示范对话会覆盖在原文上面；你在 `data/prompts/` 里自己建的每一个人格，都会新建一个对应的人格；开发模式映射到出厂的软件工程师人格。如果新版里已经有同名的人格，迁移程序不会新建，而是直接使用已有的人格。人格的子系统和插件开关在新版里没有对应的功能，会写进报告。
- **会话**：每个会话会导出成一个只读存档，你可以翻看、搜索，但是不能接着聊；文字、工具调用和结果、上传的附件都会保留。摘要行是派生出来的数据，不会导出。会话编号由旧编号计算得出，所以重复运行也不会重复导出。
  - QQ 里的会话会导出成对应的群或者私聊的存档。和新版的 QQ 会话一样，这些存档不进入会话列表，回合库会记录它属于哪个群。群里的一轮对话按每行开头的 QQ 号拆成每个人说的话；私聊里的一轮对话是对方说的话。
  - 旧版在压缩会话时移走的轮次（`evicted_context.db`）会按时刻插回原来的会话；如果原来的会话已经不存在，就按人格归进一个名为 `旧版被挤出的对话` 的会话。
  - 工具输出的图片、内嵌给模型看的图片、溢出的长输出会接在对应的那一条工具结果后面；AI 问你的问题（`ask_user`）、你在中途插入的话、只留下了展示转录的工具往来都会保留；子代理的会话会作为子会话，和它的主会话一起导出。

- **QQ 消息记录**：旧版记录的群聊、私聊消息会转换成通讯平台收录消息的格式（这一次迁移的目录里的 `qq-records.jsonl`），再交给 `miyu im records import` 导入通讯平台的库。通讯平台能识别已经存在的记录（重复运行时的记录，以及新版通讯平台并行接收过的那一段），不会重复导入。如果没有安装通讯平台，报告里会写明安装以后要运行哪一行命令。

- **记忆**：每个旧人格记下的知识点会导入它映射到的那个新人格，原来记下的时刻会保留；关于其他人的知识点会记在那个人名下，关于你的知识点会记在你名下。AI 关于自己的知识点和超过 120 字的知识点不会导入，报告里会写明它们在压缩包的哪一行。导入完成后，迁移程序会让新版整理一次记忆，合并和已有记忆重复的内容。重复运行不会重复导入，你删掉的知识点也不会被导回来。

- **配置和密钥**：供应商（地址、密钥、模型的上下文窗口、温度、价格）、主对话和看图使用的模型、子代理的几个模型池、搜索服务的密钥、关于你的信息、你的 QQ 号会补进新版的设置。迁移程序只补充新版没有的设置，新版已经配置过的设置保持不变。密钥会写进新版的密钥文件，报告里只写密钥的名字。新版没有对应功能的整段设置（上下文调参、显示、语音……）会写进报告。供应商编号会改成新版的写法，报告会列出改了哪些；带中文的编号后面会接一段由旧编号计算出来的字符，所以重复运行不会改名，两个供应商也不会得到同一个编号。

- **表情包**：你自己收集的每一个表情库会各自做成一个表情包的内容包，里面有图片、描述、什么时候使用、从哪里收集来的。如果已经安装了表情包软件包，内容包会直接安装；如果没有安装，内容包会留在这一次迁移的目录里，报告会写明安装以后要运行哪一行命令。

- **技能、脚本**：你自己写的技能会拷贝进新版的技能目录。和已有技能同名的技能不会覆盖已有的技能，而是改名后拷贝，并且列进报告；技能里的链接不会跟随、不会拷贝，报告会写明有几个；如果技能的 `SKILL.md` 本身是指向技能外面的链接，整个技能都不会拷贝，报告会写明。你自己写的脚本在新版里格式不同，所以会原样留在压缩包里，报告会逐个列出；如果官方软件源里已经有同名的新软件包，报告会提示你安装。旧版包管理器安装的内容不会拷贝，报告里会写明到官方软件源安装哪个新软件包。

- **知识库**：你自己放进旧版的文档会拷贝进新版的一个名为 `旧版知识库` 的库（`root/kb/legacy/`），由新版自己建立索引；旧版内置的默认库不会迁移。如果旧版的清单 `kb_meta.db` 已经损坏、无法读取，报告会写明原因，文档会留在压缩包里。

- **文件**：旧版为你保存的图片、文档、工具生成的产物（按会话分好）、工作目录，会拷贝进新版的图片、文档、工作区目录；如果新版里已经有同名但内容不同的文件，迁移程序不会覆盖，而是改名后拷贝，并且列进报告。旧版里分享给其他人的内容不会迁移。

- **搜索脚本的登录状态**：闲鱼的登录状态会拷贝进新软件包 `goofish` 的状态目录（前提是已经安装了这个软件包）；知乎、小红书、哔哩哔哩的搜索在新版里还没有对应的软件包，它们的登录状态会留在压缩包里；哔哩哔哩开播的新软件包安装以后需要重新登录。报告里只写站点和条数，不写 Cookie 的内容。

- **赞助记录**：赞助记录会交给通讯平台的赞助插件，导入插件的账本，原来的时刻、金额、汇率保持不变；插件能识别已经存在的记录，重复运行不会重复导入。如果没有安装插件，报告会写明安装以后重新运行；如果插件或者 Miyu 的版本太旧，报告会写明升级哪一个以后重新运行。旧版没有折算成人民币的外币会记成「未换算」，不算作 0 元。如果会话库已经损坏、无法读取，报告会写明原因，记录会留在压缩包里。时刻无法解析的那几笔记录（没有写时区的按 UTC 解析）不会迁移，会留在压缩包里，报告会写明有几笔；其他记录正常导入。

- **不迁移的内容**：用量、按上方向键调出的输入历史、QQ 的图片、好感度这类插件数据、记忆的日记和旧向量、定时提醒等内容会留在压缩包里，报告会逐项写明它们在哪里、是什么格式，需要的时候你可以让 AI 按照 `给agent.json` 接着迁移。派生出来的缓存由新版自己重建。旧版在数据根外面安装过的东西，报告只说明它们是否还在：如果 `~/.local/bin/miyu` 是新版的（安装脚本创建的、指向 `~/.local/lib/miyu/` 的链接，或者写着 `miyu-remake` 的包装脚本），报告会如实说明，并提醒你不要删除；旧版 fish 的那份配置按 `$XDG_CONFIG_HOME/fish/conf.d/miyu.fish` 查找，没有设置这个变量时查找 `~/.config/fish/conf.d/miyu.fish`；如果它是指向已经不存在的位置的链接，报告同样会列出，并写明它原来指向哪里。旧版的终端集成写进 bash、zsh 启动文件（`~/.bashrc`、`~/.bash_profile`、`~/.bash_login`、`~/.profile`、`~/.zshrc`、`$ZDOTDIR/.zshrc`）的那一段，报告会写明它在哪个文件的第几行到第几行；迁移程序只报告、不修改。你在新版里运行 `miyu shellhook install` 安装这种 shell 的集成时，新版会先备份这一段，再删掉它（fish 的那份也一样）。报告的最后一节写明压缩包在哪里、什么时候可以删除旧目录（删除由你自己来做）。

新版核心不读取旧格式的任何一个字节：等旧用户都迁移完成以后，这个软件包会下架，仓库会归档。

## 开发

开发时运行以下检查：

```
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

这些检查和 CI（`.github/workflows/ci.yml`，在 Linux、macOS、Windows 三个平台上运行）执行的检查相同。
