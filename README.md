# miyu-migrate

把旧版 Miyu（0.7.x）的数据目录迁进新版 Miyu。新版的软件包：装上以后多一条 `miyu migrate`。

```
miyu pkg install miyu-migrate
mv ~/.miyu ~/.miyu-0.7        # 先停掉旧版，再把旧目录挪开
miyu migrate ~/.miyu-0.7
```

它先把旧目录整个打成压缩包、逐个文件核对，然后只从解出来的副本读，经新版核心的协议写进去，最后出两份报告：一份给人看，
一份给 agent 读（写明没迁的东西在压缩包里的哪个路径、旧格式是什么样，要的时候让 agent 接着迁）。旧目录不动。压缩包和报告放在
新数据根的 `root/documents/旧版 Miyu 迁移/<时刻>/`：人看得见，卸了这个包也不删，跟着数据根一起备份。

迁移程序连新版核心的身份就是在终端里跑它的人（读数据根的 `run/token`），核心没在跑会照 `miyu core` 拉起。动手前会先查：旧版
停了没有（`daemon.lock`），盘够不够（放压缩包的那块要旧目录大小的两倍：压缩包按不压缩算，加上解出来核对的那一份；解出来的
那一份在迁移包的状态目录里，用完就删）。

现在迁的：

- **人格**：旧版的 Miyu 新建成名字叫 Miyu 的人格（提示词取旧版原文，`crates/miyu-migrate/legacy/`，你改过的角色扮演提示、
  示范对话盖在上面）；`data/prompts/` 里自己建的每一个新建一个；开发模式映射到出厂的软件工程师。新版里已经有同名人格的不建，
  直接用它。人格的子系统、插件开关新版没有对应，写进报告。
- **会话**：每个会话导成一个只读存档（能翻、能搜，不能接着聊），字、工具调用和结果、上传的附件都在；摘要行是派生的，
  不导。会话编号由旧编号算出来，重跑不会重复导。
  - QQ 里的会话导成那个群、那个私聊的存档（和新版的 QQ 会话一样不进会话列表，回合库记得是哪个群）：群里的一轮照每行开头的
    号拆成每个人说的话，私聊是对方说的。
  - 旧版压缩时搬走的轮（`evicted_context.db`）照时刻插回原来的会话；原来的会话不在了的，照人格归进一个「旧版被挤出的对话」。
  - 工具出的图、内嵌给模型看的图、溢出的长输出接在那一条工具结果后面；她问你的问题（`ask_user`）、你中途插的话、只留了展示转录
    的工具来回都在；子代理的会话作子会话，和它的主会话一起导。

- **QQ 消息记录**：旧版记下的群聊、私聊消息转成 im 收的写法（这一次的目录里的 `qq-records.jsonl`），交 `miyu im records import`
  导进 im 的库；im 认得出已经有的（重跑、新 im 并行接过的那一段），不会多出来。im 没装的，报告里写装上以后跑哪一行。

- **记忆**：每个旧人格记下的知识点导进映射到的那个新人格（原来记下的时刻留着），说的是别人的记成那个人的，说的是你的记成你的；
  她自己的、超过 120 字的不导，报告里写在压缩包的哪一行。导完让新版整理一次，合掉和已经记下的重复。重跑不会重复导，删掉的也不会
  导回来。

- **配置和密钥**：供应商（地址、key、模型的窗口、温度、价格）、主对话和看图的模型、子代理的几个池、搜索的 key、关于你、你的 QQ 号，
  补进新版的设置；只补新版没有的，新版已经配过的不动。key 写进新版的密钥文件，报告里只写名字。新版没有对应的整段（上下文调参、
  显示、语音……）写进报告。

- **表情包**：你自己收的那几个库各做成一个表情包的内容包（图、描述、什么时候用、从哪收来的），装着表情包的直接装上；没装的包留在
  这一次的目录里，报告写装上以后跑哪一行。

- **技能、脚本**：你自己写的技能拷进新版的技能目录（同名的不覆盖，改名并列进报告）；自己写的脚本新版格式不一样，原样留在压缩包里，
  报告逐个列出，官方源里已经有同名新包的提示装。旧版包管理器装的不拷，报告里写到官方源装哪个新包。

- **知识库**：你自己放的文档拷进新版的一个库「旧版知识库」（`root/kb/legacy/`），新版自己建索引；旧版内置的默认库不迁。

- **文件**：旧版给你存的图片、文档、工具产出的产物（照会话分好）、工作目录，拷进新版的图片、文档、工作区目录；新版里已经有同名
  不一样的不覆盖，改名并列进报告。以前给别人的分享不迁。

- **搜索脚本的登录态**：闲鱼的拷进新包 `miyu-scripts-goofish` 的状态目录（包装着的话）；知乎、小红书、B 站搜索新版还没有包，登录态
  留在压缩包里；B 站开播的新包装上以后重新登录。报告里只写站点和条数，不写 cookie。

- **赞助记录**：交 im 的赞助插件导进它的账本（原来的时刻、金额、汇率照旧），插件认得出已经有的，重跑不多；插件没装的报告写装上
  以后重跑。

- **没迁的**：用量、上键历史、QQ 的图片、好感度这类插件数据、记忆的日记和旧向量、定时提醒这些留在压缩包里，报告逐样写在哪、什么格式，
  要的时候让 agent 照 `给agent.json` 接着迁；派生的缓存新版自己重建；数据根外面旧版装过的只报在不在。报告最后一节写压缩包在哪、什么时候
  可以删旧目录（删由你自己来）。

新版核心一个字节都不认旧格式：旧用户都迁完以后，这个包下架、仓库归档。

## 主人在真数据根上跑

主人这台的情况和上面那三行不一样：新版的数据根由 `MIYU_HOME` 指到 `~/.cache/miyu-tui-home`，不是 `~/.miyu`，所以旧目录
`~/.miyu` 不用挪，原地交给迁移程序就行。下面是 fish，一行一个代码块，照顺序敲；每一步都可以停下来看。

**零、先确认两件事**

- 核心要认得「只带子命令的包」（核心那边改完会给出最低的提交号）；部署还是 11-03 那版（`43ff9ee97`）的，先换核心。
- 用临时部署的包装脚本（`~/.local/bin/miyu`）的：它照子命令转交，列表里要加上 `migrate`，否则 `miyu migrate` 会打开终端界面。

**一、装包**（二选一）

本地的包文件（CI 打出来的，或者自己在仓库里把程序拷进 `miyu-migrate/bin/`、许可证拷进 `miyu-migrate/LICENSE` 以后用
`miyu pkg pack miyu-migrate --target linux-x86_64` 打的 `.miyu`，路径换成实际的；装之前会问一句，答 Y）：

```fish
miyu pkg install ./miyu-migrate-0.1.1-linux-x86_64.miyu
```

或者等它进了官方源：

```fish
miyu pkg install miyu-migrate
```

装好看一眼能不能转交过去（只印用法，不动任何东西）：

```fish
miyu migrate --help
```

**二、停旧版核心**（8300 那个；什么时候停由主人自己定，停了旧版的 QQ、网页就断了）

先看它在不在跑：

```fish
ss -ltnp | grep ':8300'
```

在跑的照旧版自己的命令停。本机的 `miyu` 已经换成新版的包装脚本，旧版程序是改了名的那一份：

```fish
~/.local/bin/miyu.0.7.0-local.bak daemon stop
```

没停也不要紧：迁移程序动手前会对 `~/.miyu/daemon.lock` 试锁，旧核心还拿着就报「旧版还在跑」，一个字都不写。

**三、给新数据根拍一份底**（回退用；先关掉终端界面、网页这些会把核心拉起来的头，新版的 QQ 也会断一会儿）

```fish
miyu core stop
```

```fish
cp -a --reflink=auto ~/.cache/miyu-tui-home ~/.cache/miyu-tui-home.before-migrate
```

**四、迁**

```fish
miyu migrate ~/.miyu
```

迁移程序会自己把核心拉起来。先把 `~/.miyu` 整个打成压缩包、逐个文件核对，再从解出来的副本迁；`~/.miyu` 本身只读不写。

**五、看报告**

跑完印两行路径。都在新数据根的 `root/documents/旧版 Miyu 迁移/` 里，一次一个目录，目录名是这一次的时刻（UTC）：

```fish
ls ~/.cache/miyu-tui-home/root/documents/旧版\ Miyu\ 迁移/
```

每个目录里有 `报告.md`（给人看的）、`给agent.json`（给 agent 接着迁用的）、`miyu-0.7.tar.zst`（旧目录的整个压缩包）和
`miyu-0.7.manifest.json`（压缩包里每个文件的哈希）；im、表情包没装的，还有留着待导的 `qq-records.jsonl` 和表情包的包。

```fish
less ~/.cache/miyu-tui-home/root/documents/旧版\ Miyu\ 迁移/*/报告.md
```

压缩包是旧目录唯一的整份备份，放在数据根里，`miyu pkg remove miyu-migrate` 不会删它；不要了自己删这个目录。

**六、出了问题怎么退**

旧根 `~/.miyu` 本来就没动：迁移失败也好、迁完不满意也好，旧版照旧能起。要撤的是新数据根里导进去的东西。

整个撤（迁完马上发现不对的时候用；迁移以后在新版里新聊的、新改的也会一起回到迁移之前）：

```fish
miyu core stop
```

```fish
mv ~/.cache/miyu-tui-home ~/.cache/miyu-tui-home.after-migrate
```

```fish
mv ~/.cache/miyu-tui-home.before-migrate ~/.cache/miyu-tui-home
```

这一次的报告和旧目录的压缩包在 `.after-migrate` 的 `root/documents/旧版 Miyu 迁移/` 里，看完再删。

只撤一部分：报告里每一类都写了写到了哪、迁了几条、哪些改了名。直接放进数据根的几样，删掉对应的目录就是撤：

- 技能：`root/skills/` 下报告列出的那几个
- 知识库：`root/kb/legacy/`（整个「旧版知识库」）
- 文件：`root/pictures/`、`root/documents/` 里报告列出的、`root/documents/旧版产物/`、`root/workspace/旧版/`（`root/documents/旧版 Miyu 迁移/`
  是压缩包和报告，不是迁过来的文件，别一起删）
- 闲鱼登录态：`root/state/scripts/miyu-scripts-goofish/goofish/legacy/`
- 表情包：`miyu pkg remove legacy-memes-<库名>`（报告里写了是哪几个）

人格、会话存档、记忆、配置和密钥、QQ 消息记录、赞助记录是经核心和 im 写进库里的，没有逐条撤的命令：要撤这几样，用上面的整个撤。
